OCR Engine Benchmark

Making scanned Indian legal documents machine-readable — 9 engines tested on a real 24-page scanned GST advance ruling.

📅 2026-09-05 🖥 macOS 26.5 · Apple Silicon arm64 🐍 Python 3.14.7 📄 24-page image-only scan (0 chars native text)

The problem

The GST Council publishes ~4,300 advance-ruling orders as scanned image PDFs with no text layer (~65,000 pages total). We need them searchable in a local database. This benchmark answers: which OCR engine should do it, and what will it cost in time/quality?

Key discovery: the scans are natively ~72 dpi (612×1008 px). Rendering at 200–300 dpi is just upscaling — it buys nothing. The ruling date 30.07.2026 exists only as handwriting, making this a genuinely hard test.

Recommendation for the 4,300-document / 65,000-page corpus

🥇 Primary: macOS Vision via PyObjC — $0, ~14 h (→ ~5 h parallelized)

Highest factual accuracy of any local engine (only one with the exact GSTIN), zero download, robust on low-res 72 dpi scans. Caveats: macOS-only, Hindi dropped (acceptable — Hindi passages mirror English verbatim in this document class), handwriting unreliable.

🥈 If Hindi must be kept: Mistral OCR API — ≈ $130 for the whole corpus

VLM-class quality (Surya-equal) at API speed. Very reasonable against ~600 CPU-hours of local VLM OCR. Surya itself is impractical locally (610 h on this Mac), though it's the best raw quality if run on a rented GPU.

🥉 Free triage layer: ocrmypdf — 0.26 s/page

Add a searchable text layer + fact-check (ruling-number regex); escalate failures to Vision/Mistral. Also: don't re-render above 150 dpi — the scans are natively ~72 dpi; higher dpi adds no information.

PaddleOCR — solved the install, lost the speed race

PaddleOCR 3.7 does run when you install it under a Python 3.12 venv (only 3.14 lacks a wheel) — and it delivered Surya-class quality: exact GSTIN and it read the handwritten date. But at 33 s/page on CPU it's ~600 h for the corpus, with no GPU option on this Mac. Worth revisiting only on a CUDA box. No Devanagari support in 3.7 either.

Environment & reproducibility

Benchmarked on macOS 26.5.1 (Apple Silicon), Python 3.14.7, tesseract 5.5.2 (homebrew). Surya 0.22.1 runs surya-ocr-2 as a 1.4 GB GGUF via llama.cpp. EasyOCR ran on torch 2.14 CPU. PaddleOCR publishes no cp314 macOS-arm64 wheel. All multi-GB venvs and model caches were deleted after capture.
